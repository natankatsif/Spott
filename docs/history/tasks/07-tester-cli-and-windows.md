# Задача 07 — консольный поиск для тестировщика + запуск проекта на Windows

Прочитай `docs/tasks/06-document-updates.md`, свой отчёт по 06 и код `packages/retrieval` (`pipeline.py`, `tools.py`). Человек у компьютера. Mac — 8 ГБ RAM, реранкер выключен.

## Зачем
Это промежуточный этап перед ИИ-агентом (задача 09).
1. Тестировщик должен сам гонять поиск из консоли, без фронта и без LLM, и отмечать хорошие и плохие выдачи. Его отметки станут нашим честным eval.
2. Следующим шагом (задача 08) тестировщик будет **на своём Windows** обходить и скачивать все 40 сайтов, пока мы делаем агента. Значит, проект обязан ставиться и работать на Windows с первого раза. Проверить это на Windows мы можем только через CI, поэтому CI обязателен.

## Правила кода (проверю)
- `uv run ruff check .` и `uv run pytest` зелёные во всём workspace.
- Цифры в отчёте — только из вывода скриптов.
- Коммит на пункт.
- Никаких LLM, никакого обхода новых сайтов.

## A. Долги задачи 06 (сначала)
1. Прогони `update.sh` на текущих данных и вставь в отчёт его итоговую сводку как есть. Ожидаем почти ноль пересчитанных эмбеддингов.
2. Убедись, что в Postgres не осталось старых `doc_id` вида `file:<sha>`. Покажи вывод:
   `SELECT count(*) FROM chunks WHERE doc_id ~ '^file:[0-9a-f]{64}$'` (то же для `lines`). Должно быть 0. Если не 0 — миграция или переиндексация.
3. Перепрогони `run_line_eval.py` на очищенном `lines.yaml`. В отчёте таблица «до чистки (цифры 05) / после».

## B. Консольный поиск `qsearch`
Консольная команда в пакете `retrieval` (`[project.scripts]`), запуск: `uv run qsearch`. Вызывает **только** существующие `retrieve()` и `tools.py`, никакой второй реализации поиска.

1. **Интерактивный режим** (REPL):
   - Модель грузится один раз, после этого печатается «готово».
   - Вводишь вопрос — получаешь топ-5 результатов. Для каждого:
     - номер и score;
     - язык (RO/RU);
     - сайт и название документа;
     - страница;
     - найденная строка (подсвечена цветом) и 1 строка контекста вокруг;
     - `deep_link`.
   - Внизу — время поиска в мс.
2. **Команды:**
   - `:grep <фраза>`, `:toc <doc_id|номер>`, `:open <doc_id|номер> [строка]` — обёртки над tools;
   - `:lang ro|ru|all` — фильтр языка;
   - `:k N` — сколько результатов показывать;
   - `:help`, `:q`.
3. **Отметки тестировщика:**
   - `:ok N` — правильный ответ в результате N;
   - `:bad` — правильного ответа нет в топе;
   - `:none` — информации в корпусе нет, это правильное поведение;
   - `:note <текст>` — комментарий.

   Всё пишется в `data/test_logs/<дата>.jsonl`: время, вопрос, язык, `chunk_id`/`line_id` результатов, отметка, заметка, `git rev-parse --short HEAD`. Логи в git не попадают.
4. **Разовый режим:** `uv run qsearch "вопрос" [--json] [--lang ro]` — для скриптов.
5. **Сводка:** `uv run qsearch --report` печатает по логам:
   - сколько вопросов;
   - процент `ok`;
   - средний ранг правильного ответа;
   - список `bad` для разбора.
6. **Разноязычный поиск.** bge-m3 многоязычный, значит вопрос на RU должен находить RO-документы, и наоборот. Добавь в `eval/` маленький набор из 10 пар «вопрос RU → gold-строка RO» и 10 пар «вопрос RO → gold-строка RU» (если RU-документов хватит) и покажи hit@5 отдельно. Перевод не делаем: это будет в задаче 09.
7. **Кодировка:** русский и румынский текст (ș, ț, ă, ы) корректно печатается в Windows-консоли. В начале `sys.stdout.reconfigure(encoding="utf-8")`, цвета — через `colorama` или `rich`.

## C. Windows-готовность
1. **UTF-8 везде.**
   - Включи правило ruff `PLW1514` (unspecified-encoding) и почини все `open()`, `read_text()`, `write_text()`: у всех должно быть `encoding="utf-8"`.
   - На Windows кодировка по умолчанию cp1252, без этого всё сломается.
2. **Скрипты без bash.**
   - Перепиши `update.sh`, `overnight.sh`, `export_index.sh` и `import_index.sh` на Python: `uv run python -m tools.update` и т. п. (модуль на твой выбор).
   - `.sh` оставь тонкими обёртками для Mac.
   - `pg_dump` и `pg_restore` вызывай через `docker exec`, чтобы на Windows не нужен был локальный Postgres-клиент.
3. **Пути.**
   - Только `pathlib`, никаких склеек строк с `/`.
   - Имена файлов в `data/`: без символов `:?*<>|"`, длина ≤ 120 символов (длинное имя → обрезка + короткий хеш), не заканчиваются точкой или пробелом.
   - Тест на это.
4. **OCR на Windows.** Tesseract с языками `ron` и `rus`. Путь к `tesseract.exe` можно задать через `.env` (`TESSERACT_CMD`), если его нет в PATH.
5. **`uv run python -m tools.doctor`** — проверка окружения, каждая строка ✅ или ❌ с подсказкой, как починить:
   - Python ≥ 3.14 и `uv`;
   - `.env` есть;
   - Docker запущен, база доступна, расширения `vector`/`pg_trgm`/`unaccent` на месте;
   - `tesseract --list-langs` содержит `ron` и `rus`;
   - свободно ≥ 20 ГБ на диске, RAM;
   - устройство для модели (cuda / mps / cpu);
   - сайт `autosalubritate.md` отвечает;
   - кодировка консоли.
6. **CI на GitHub Actions** (`.github/workflows/ci.yml`):
   - матрица `ubuntu-latest` + `windows-latest`;
   - шаги: `uv sync`, `ruff`, юнит-тесты без БД (тесты с БД пометь маркером `db` и пропускай на CI);
   - на Windows дополнительно: `python -m tools.doctor --ci` (без Docker и сети) и `qsearch --help`.

   Цель — зелёный Windows-прогон, ссылку на него дай в отчёте. Если какая-то зависимость (torch, docling) не ставится на Windows под Python 3.14 — **остановись и напиши**, это решение команды.
7. **`docs/TESTER.md`** на русском, для человека, который видит проект впервые. Каждый шаг — команда для PowerShell:
   1. Установить Git, uv, Docker Desktop, Tesseract (с ron+rus).
   2. `git clone`, скопировать `.env.example` → `.env` (ключ OpenAI не нужен).
   3. `docker compose up -d`.
   4. Импорт готового дампа индекса (файл дадим отдельно, в git его нет).
   5. `uv sync`, `doctor`.
   6. `qsearch`: как искать и как ставить отметки, 5 примеров вопросов.
   7. Как отправить нам `data/test_logs/`.
   8. Раздел «Если сломалось»: типичные ошибки и что делать.

   Раздел про обход сайтов пока **не писать** — это задача 08.
