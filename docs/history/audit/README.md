## Коротко о главном

1. **Удалённое с сайтов не уходило из ответов.** Каждая обработка из админки индексирует только свой сайт,
   а очистка удалённых документов работала только при полной переиндексации. Документ, пропавший с сайта,
   страница, ставшая 404 или пустой, оставались в индексе навсегда. (01-pipeline, I1)
2. **Одна временная ошибка сайта выкидывала документ из индекса.** Если при обновлении PDF отвечал 5xx или
   таймаутом, документ получал статус `failed` и переставал считаться действующим; первый же 404 тоже, хотя
   задумано «удалять после двух промахов подряд». (01-pipeline, D1, D2)
3. **Зависшие обработки.** Если worker перезапускался посреди обработки, она навсегда оставалась «идёт»,
   и источник нельзя было обновить («ещё выполняется»). (01-pipeline, W1)
4. **Лимиты обходятся подменой заголовка.** Ограничение попыток входа в админку и частоты вопросов брали
   IP из первого значения `X-Forwarded-For`, которое задаёт сам клиент. Пароль админки можно было перебирать
   без ограничений. (03-backend-api, S1)
5. **Админка на телефоне.** Таблица источников не помещается по ширине, вкладки обработок ломаются,
   категории показываются сырыми ключами (`urban_utilities`), а «Частые причины» всегда пустые, потому что
   в чате нет способа указать причину дизлайка. (04-ui)

Все пункты выше исправлены в `audit-fixes`. Подробности и проверка в [05-fixes.md](05-fixes.md).
