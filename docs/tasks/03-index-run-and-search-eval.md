## Что сделать (по порядку, коммит на пункт)

3. **Поднять инфраструктуру**: `docker compose up -d` (из корня), `uv sync`. 4. **Индексация**: `uv run python -m indexing`. В отчёт: время, число документов/чанков; проверка консистентности SQL-запросом — чанков в БД == чанков в `data/chunks/*.jsonl`, `embedding IS NULL` == 0, устройство (mps/cpu).
5. **Смоук-eval поиска** — `offline_indexation/eval/search_smoke.yaml` + `uv run python -m indexing.eval_smoke`:

   - для каждого — ожидаемый ответ: `doc_id` или `site` + ключевая фраза, которая должна быть в найденном тексте; для «нет в корпусе» — `expected: none`;
   - скрипт считает **hit@1, hit@5, MRR** отдельно для трёх режимов: только вектор, только FTS, гибрид RRF; а для «нет в корпусе» печатает лучший скор (понадобится для порога отказа). Плюс средняя латентность запроса (эмбеддинг + SQL).

6. **Ночной сбор корпуса** (последний пункт, запускается в фоне и работает, пока все спят):

## Дополнение (сверка с лучшими практиками) — сделать ДО пункта 4 «Индексация»

**A. Стемминг RO/RU в full-text вместо `simple`.** В задаче 01 было написано, что румынского стеммера в Postgres нет, — это ошибка постановки: в Postgres встроены snowball-конфигурации `romanian` и `russian`. Сейчас `autorizația` / `autorizației` / `autorizare` не совпадают между собой.
- Создай конфигурации `ro_unaccent` и `ru_unaccent`: `CREATE TEXT SEARCH CONFIGURATION ro_unaccent (COPY = romanian); ALTER … ALTER MAPPING FOR hword, hword_part, word WITH unaccent, romanian_stem;` (аналогично для `russian`). Идемпотентно, в `INIT_SQL`.
- `tsv` = `to_tsvector(<конфиг по lang чанка>, embed_text)`; для `en`/`uk` используй `simple`. Проверь, что generated column с выбором конфигурации по `lang` работает (иначе — обычная колонка, которую заполняет индексатор).
- Запрос: `to_tsquery('ro_unaccent', q) || to_tsquery('ru_unaccent', q)` (OR обеих версий), с тем же отбором значимых слов, что в `build_fts_query`.
- Тест на уровне SQL (в отчёте, не в pytest): `autorizația` находит чанк с `autorizației`; `мусор` находит `мусора`.

**B. Реранкер как 4-й режим в смоук-eval.** `BAAI/bge-reranker-v2-m3` (Apache 2.0, мультиязычный) через `sentence-transformers` `CrossEncoder`, модуль `indexing/rerank.py` с ленивой загрузкой, как у эмбеддингов. Режим «гибрид top-50 → реранкер → top-k». В eval печатай для 4 режимов hit@1/hit@5/MRR и латентность, а для вопросов «нет в корпусе» — **максимальный скор реранкера** рядом с распределением скоров правильных ответов (это будущий порог отказа: косинус для этого не годится, скор реранкера — годится лучше).

**C. Сохранить в индексе поля для онлайн-части** (дёшево сейчас, дорого потом): `page_sizes` (из `pages[]` распарсенного файла) в `documents`; `parent_legal_path` в `chunks` (всё, кроме последнего элемента `legal_path`) — для «small-to-big»: найти пункт, а в LLM отдать всю статью.
